Threat Modeling Agentic AI Platforms

A MAESTRO methodology worked end to end against a representative enterprise agentic AI architecture, cross-referenced against OWASP LLM Top 10, MITRE ATLAS v4, and NIST AI RMF 1.0.

Purpose: A worked threat model for an enterprise agentic AI platform, enumerating and scoring threats across the agentic attack surface using the MAESTRO layer taxonomy. MAESTRO was designed for agentic AI systems; its seven layers map directly onto the class of system it targets: an LLM endpoint, proxy middleware, managed runtime, data integrations, delegation chain, and ReACT engine.

About this document

Threat model derived from code-level inspection and adversarial red team testing of the agent framework. Proprietary credentials, endpoint URLs, infrastructure identifiers, vendor-specific configuration state, and customer data are deliberately excluded. The architecture is generalized to the pattern rather than to any single deployment.

Assessment approach: Each finding carries a MAESTRO layer, unique ID, attack vector, impact, mitigation status, and DREAD score. Red team findings are reconciled with verdicts based on code-level analysis of the framework.

M - Model Layer Findings

M - Model Layer Findings

Threats intrinsic to the LLM inference endpoint: prompt injection, jailbreak, system prompt leakage, training data extraction, and model version integrity.

IDTitleAttack VectorImpactStatusDREAD
M-1 Direct Prompt Injection Adversarial user input attempts to override system prompt instructions, hijack agent persona, or unlock restricted tool calls Agent executes attacker-controlled actions; tool scope escape; cross-user data access if identity also compromised Mitigated 28
M-2 Indirect Prompt Injection via Tool Output Adversarial content in tool results (RAG documents, SQL rows, KG data) contains injection instructions that the model treats as authoritative; boundary markers are best-effort, not cryptographic Model executes attacker-embedded instructions; memory poisoning; privilege escalation via agent confusion Partial 30
M-3 Jailbreak via Encoding / Obfuscation Base64, ROT13, hex, reversed text, homoglyph substitution, or l33tspeak used to encode malicious instructions and evade input filters Filter bypass; model executes hidden payload; safety controls circumvented Mitigated 22
M-4 System Prompt Extraction Roleplay, authority-escalation, translation, or encoding attacks to recover system prompt content Defensive instructions disclosed; enables targeted bypass crafting Partial 27
M-5 Training Data Extraction Repetition attacks or targeted prompts to recover memorised training data, including proprietary or sensitive content Sensitive-data exposure; proprietary data disclosure; regulatory liability Mitigated 15
M-6 Stale Model Version Serving Prior model version with looser prompt controls served by name from registry; no alias lock prevents this Agent runs with weakened defences; injection vulnerabilities believed remediated reappear Partial 20

Mitigation Evidence

  • M-1: the boundary-marking component wraps every tool output in per-request HMAC nonce delimiters before it enters message history; the tool registry is static, loaded at deployment-packaging time with no runtime registration path; SSO-derived identity enforced server-side
  • M-2 partial: Boundary markers provide defense-in-depth but model compliance is not cryptographic; the LTM pre-write race (S-1 below) means adversarial facts can persist before the fact-checking module validates them; the memory-trust module adds write-side confidence tagging and read-side filtering
  • M-3: Red team adversarial encoding tests (Base64, ROT13, hex, reversed) and perturbation attacks (homoglyph, character swap, l33tspeak) all produced correct model refusals; AI Gateway input and output safety filters provide additional coverage
  • M-4 partial: Direct, encoded, and translated extraction attacks blocked; authority escalation framing was a false positive; full extraction not demonstrated but residual surface remains
  • M-5: Foundation model provider safeguards; AI Gateway PII detection and output safety filters active; membership inference testing did not confirm extraction
  • M-6 partial: Model registry has multiple active versions; no alias lock prevents serving older versions by name; registry governance control required
A - Application Layer Findings

A - Application Layer Findings

Threats in the chat frontend and ProxyMiddleware, the only user-facing ingress. Correct identity derivation here is the single most important control for a large set of findings.

IDTitleAttack VectorImpactStatusDREAD
A-1 Trusted-Header Identity Forgery Attacker with a direct path to the chat-frontend container (bypassing the platform reverse proxy) sets the SSO-identity header to an admin address; the proxy derives an admin identity from it Admin-level agent access; cross-user data access; full session impersonation Mitigated 22
A-2 Direct Endpoint Bypass via User PAT User generates a personal access token and calls the serving endpoint directly, supplying arbitrary custom_inputs including user identifier, bypassing all proxy-enforced controls All proxy controls bypassed; arbitrary user-identity injection; A-4 / S-5 attack surface materialises Mitigated 25
A-3 Account Registration Forgery If trusted-header auth is not configured, attacker registers with an admin email address directly in the chat frontend Admin access to all stored conversations Mitigated 18
A-4 User-Identifier Injection via custom_inputs Via A-2 path (when open): attacker sends a crafted custom_inputs payload with a target user identifier to query another user's memory and tools Cross-user data access; unauthorised memory reads Mitigated 30
A-5 SSE Stream Content Manipulation On-path attacker manipulates SSE chunks between the proxy and serving endpoint, or triggers response-parsing edge cases to swallow legitimate output Tampered agent response displayed to user; partial data loss Mitigated 18
A-6 Feedback Rate-Limit Bypass Attacker submits more than a small configured per-user cap on assessments per trace by supplying a different user_id in the POST /v1/feedback body; the rate-limit check uses this body field, not the SSO-derived identity Evaluation-store assessment pollution; HITL threshold calibration corrupted via the feedback adapter Mitigated 18
A-7 SQL Injection via Evaluate Endpoint the evaluation-submission handler previously constructed a raw SQL INSERT using a manual string-escaping helper (single-quote doubling only); attacker-controlled form fields were not parameterised SQL injection into the evaluation-results table via the operational database; data corruption; potential privilege escalation Mitigated 35

Mitigation Evidence

  • A-1: the SSO-identity header is injected by the platform reverse proxy (infrastructure-controlled); user browser sessions cannot set it; a trusted-header config flag enforces this; trusted-header auth configured with manual admin assignment
  • A-2: Serving endpoint invocation is restricted to the application service principal only; user-scoped tokens cannot invoke the endpoint directly, collapsing the A-4 attack surface
  • A-3: Trusted-header auth configured; direct registration with arbitrary email blocked at platform level
  • A-4: the user identifier is always derived server-side from the SSO header; user-supplied custom_inputs value is overwritten before reaching the model; the A-2 control makes this surface structurally unreachable
  • A-5: SSE relay operates over authenticated TLS to the serving endpoint; JSON-stripping logic is local to the proxy container; on-path attack requires platform-level breach
  • A-6 partial: the per-user feedback counter enforces a small configured limit via an evaluation-store API lookup; feedback user_id is bound to the SSO-derived identity rather than the POST body field, closing both the rate-limit bypass and the G-4 threshold poisoning surface
  • A-7: the evaluation-submission handler uses parameterised SQL statements; the manual string-escaping helper has been replaced with parameterised binding throughout the evaluate endpoint path; the agent SQL tool path independently uses pre-defined parameterised functions

E - Environment Layer Findings

Threats in the managed serving container, secrets management, model artifact integrity, and deployment pipeline. Compromise at this layer renders all higher-layer controls moot.

IDTitleAttack VectorImpactStatusDREAD
E-1 Code-Path Tampering at Deploy Time Malicious Python modules substituted into bundled code paths before deployment packaging; no integrity check on bundled artifacts at time of threat identification Arbitrary code executes on every inference request for all users Mitigated 38
E-2 Model Registry Version Swap Workspace user with EDIT on the model registers a malicious version; no alias lock enforced; any version can be served by name Backdoored model executes for all users on next endpoint update; prompt injection defences bypassed Partial 33
E-3 Secrets Exposure via Error Messages Exception paths triggered that include token or secret material in the HTTP response body Service-principal token or delegation-signing secret exfiltrated; lateral movement to all SP-permitted resources Mitigated 28
E-4 Hardcoded Token in Version-Controlled Source PAT committed in a deployment script; anyone with repository read access acquires direct endpoint invocation capability Unauthorised endpoint access; lateral movement; direct invocation bypassing proxy controls Mitigated 33
E-5 Service Principal Token Exfiltration + Pivot SP token leaked from serving environment; used directly against platform APIs Full SP-scope access to the data catalog, storage volumes, and warehouse tables; lateral movement Mitigated 35
E-6 Missing Delegation-Signing Secret at Runtime the secret-loading function in the delegation-signing module raises a hard error if the secret is absent; if this exception is swallowed, the HMAC chain may operate unsigned Multi-agent HMAC delegation chain disabled; confused-deputy attack surface opens Mitigated 32

Mitigation Evidence

  • E-1: Every bundled code-path file is SHA-256 hashed into a manifest at deploy time and stored as a named model artifact; at runtime startup each file is re-hashed before any user code executes, failing closed on mismatch
  • E-2 partial: No alias lock on model registry; any workspace user with EDIT on the model can push a new version; recommended control: registry alias lock + deployment approval gate
  • E-3: Secrets scope syntax prevents token exposure in response body; exception handlers in the serving framework mask token material before returning to caller; AI Gateway safety filters provide secondary coverage
  • E-4: The PAT identified in the deployment script has been rotated and removed; secrets are sourced exclusively from the platform secrets manager at runtime
  • E-5: Secrets scope access restricted to named principals; platform service-principal credentials stored in the platform secrets manager, not in source
  • E-6: the secret-loading function raises a hard error with no hardcoded fallback; serving endpoint fails to start if the secret is absent; fail-closed behaviour is the correct control

S - System Layer Findings

Threats in data store integrations, covering table-store LTM tables, vector index, SQL warehouse, knowledge graph, and trace/inference log stores. Each is an independent write or read surface.

S-4 SQL Injection via Agent Tool Chain Attacker injects SQL fragment into a parameter passed to a SQL tool; the SQL tool wrapper expands it under the SP's warehouse privileges Arbitrary SQL executed under SP's warehouse privileges; data exfiltration; schema manipulation Mitigated 40
S-5 Cross-User Memory Leakage Via direct PAT path (A-2, when open): user supplies a different user identifier in custom_inputs and reads another user's LTM facts Unauthorised access to another user's persistent context, including sensitive conversation history Mitigated 30
S-6 Inference Table Exposure Full request/response history in the inference log table is accessible without column masking; unauthorised read yields historical sensitive conversations Historical sensitive conversations exposed; audit risk Partial 25
S-7 RAG Over-Retrieval Document retrieval returns content beyond a user's intended authorisation scope; no document-level ACLs on the vector index Internal documents surfaced to users without explicit access Accepted 18

Mitigation Evidence

  • S-1: the fact-checking module operates as a synchronous pre-write guard on the LTM path; TrustTagger adds confidence and source classification to every write; TrustFilter enforces a minimum confidence threshold and staleness decay on reads; ContradictionQueue persists detected contradictions for review
  • S-2: KG extraction is model-driven only; no user-controlled write path exposed; testing confirmed no user-controlled write path exists
  • S-3: vector index populated from controlled batch ingestion job; no user-facing upsert API; red team testing confirmed no injection path through the controlled ingestion pipeline
  • S-4: the tool registry generates pre-defined parameterised SQL functions at deployment-packaging time; user-controlled data is never interpolated into raw SQL strings in the agent tool path; tautology and UNION SELECT injection attempts were both confirmed mitigated
  • S-5: Depends on A-2. With direct PAT invocation restricted to service principal, memory queries use the session-config user identifier (SSO-derived), not prompt content
  • S-6 partial: Inference log table present; column masking for sensitive fields is the outstanding control; recommended: apply catalog-level column security to the inference log schema
  • S-7 accepted: Homogeneous user population with equivalent clearance for all indexed content; document-level ACL tagging cost disproportionate to risk; review trigger: any differentiation of user access levels
  • S-8 partial: No per-user LTM write quota; RateLimiter throttles request rate; BudgetEnforcer tracks token consumption but not storage record count; recommended: per-user LTM row cap in the long-term memory module
  • S-9: Append-only table mode with time travel; DELETE requires MODIFY privilege not granted to the serving SP; SHA-256 hash chain across events provides tamper detection
T - Trust Relationships Findings

T - Trust Relationships Findings

Threats in inter-agent delegation, scope enforcement, and the confused-deputy problem. Primary controls are DelegationChain (HMAC-SHA256, TTL-enforced), ToolGateway (pre-tool scope checks at CRITICAL priority), and AgentRouter.

IDTitleAttack VectorImpactStatusDREAD
T-1 Relay Message Injection (Agent-to-Agent) Craft JSON written to the IPC relay message queue without HMAC signature; receiving agent executes content as a task Arbitrary tool execution in agent context; lateral movement across agents; privilege escalation Mitigated 36
T-2 Delegation Chain Tampering Attacker modifies the delegation-chain header in transit to forge a higher-privilege scope for the current agent link Agent executes tools outside its granted scope; confused-deputy privilege escalation Mitigated 32
T-3 Delegation Chain Replay A previously captured valid delegation-chain header is replayed after the TTL (default 300s) has elapsed Expired agent credentials reused; tool calls executed outside the authorised time window Mitigated 28
T-4 Confused Deputy via Plugin Hook Craft a prompt framing a privileged tool call as if from a trusted orchestrator, attempting to bypass ToolGateway.authorize() scope check on the PRE_TOOL hook Agent executes a tool outside its authorised scope; data access beyond permitted perimeter Mitigated 28
T-5 Agent Router Intent Misclassification Craft a prompt that causes the intent router's keyword matching to route the request to a higher-privilege specialised agent; the router uses keyword scoring, not LLM-based classification Unintended access to domain-specific tools; data exposure beyond intended scope Partial 22
T-6 Tier Policy Enforcement Bypass Craft prompt to invoke tier-restricted functionality; test whether tier-policy checks are model-only (prompt-dependent) or structural (code-enforced) Access to features reserved for higher-tier users without authorisation Mitigated 20

Mitigation Evidence

  • T-1: HMAC-SHA256 signing is applied to the relay's write path via a signing function; a matching verification function on the read path rejects unsigned or tampered messages when the delegation-signing secret is configured; direct filesystem injection path is closed
  • T-2: the delegation chain's signing method computes HMAC-SHA256 over the full serialised chain (user_id + all links); a timing-safe comparison prevents timing attacks; any modification to any link invalidates the signature; the tool gateway's authorization check returns a tamper-detected deny
  • T-3: Each each delegation link carries a TTL (default 300s); the chain's verification step rejects links whose timestamp is older than their TTL; expired or replayed chains fail at verify()
  • T-4: the security plugin wires the tool gateway's authorization check into the PRE_TOOL hook at the highest priority tier; scope checks fire before tool execution so a denied tool never produces side effects; the plugin registry's hook execution is called unconditionally in the LangGraph flow; no prompt can suppress a Python function call at the infrastructure layer
  • T-5 partial: the intent router uses keyword matching with a configured confidence threshold; adversarial keyword injection could shift scores; recommended: LLM-based intent classification for high-privilege routing decisions, or explicit capability matching requiring an explicit target agent identifier
  • T-6: TierPolicy enforced structurally in plugin manager; not model-prompt dependent; red team E-8 confirmed structural enforcement

R - Operations Layer Findings

Threats in the ReACT reasoning engine, plugin hook execution, HITL escalation, rate limiting, the parallel orchestrator, and the circuit breaker; these are the runtime mechanisms that govern what the agent actually does.

IDTitleAttack VectorImpactStatusDREAD
O-1 ReACT Infinite Tool Loop Craft a prompt causing the agent to call tools in a cycle without a termination condition; agent session occupies a serving slot indefinitely Serving slot starvation; denial of service for other users; disproportionate compute cost Mitigated 18
O-2 Token Flooding / Context Exhaustion Send an oversized prompt saturating the model context window; 6.6s latency increase observed in red team D-1a; the context compression component engages at a configured token threshold Latency spike; reduced throughput; disproportionate cost under scale-from-zero billing Mitigated 20
O-3 KG Write Amplification Prompts designed to trigger heavy knowledge-graph write operations; 17.35s latency observed under write-heavy load; no per-user KG write quota KG service degraded for all users sharing the tenant; cascading latency to dependent tool calls Partial 15
O-4 HITL Escalation Bypass via Category Manipulation Agent determines its own action category via LLM inference; a prompt could cause the model to classify a high-risk action as a never-escalate item, bypassing required human review High-risk decisions executed without human review; compliance gap Partial 25
O-5 Rate Limiter Degradation Exploitation Attacker drives a tenant to a configured utilisation threshold, causing the rate limiter to return degrade decisions that disable tools and reduce output length Tool availability reduced; response quality degraded; SLA breach; competitive denial of service across tenants Mitigated 18
O-6 Parallel Orchestrator Cost Amplification High-complexity request causes the complexity classifier to route to the parallel path, spawning a small worker pool of sub-agents each making independent LLM calls and tool invocations 5× token consumption per user request; rate-limit quota exhaustion; cost amplification Partial 16
O-7 Embedding Model Saturation High-volume retrieval queries with very long inputs sent to the embedding endpoint; no per-request timeout on embedding calls; rate limit relies on platform defaults Embedding endpoint throttled; RAG pipeline timeout for all users Partial 14

Mitigation Evidence

  • O-1: a configured step cap plus a consecutive-error threshold terminate the ReACT loop; the step cap is enforced by LangGraph's recursion limit; red team D-2a confirmed effective
  • O-2: Platform serving endpoint autoscaling; the context compression component trims messages at a configured token threshold, keeping context within a configured ceiling; red team D-1a observed 6.6s latency within bounds
  • O-3 partial: 17.35s latency under write-heavy load observed and accepted as architectural trade-off (accepted as architectural trade-off); no per-user KG write quota enforced
  • O-4 partial: an always-escalate category list includes high-risk decisions, financial authorisation, and sensitive-data modification — these always escalate regardless of confidence; gap is that the action category is LLM-derived and a prompt could misclassify to avoid escalation; recommended: validate category against a structural allow-list independent of model output
  • O-5: the rate limiter's token-bucket algorithm applies per-tenant quotas, priority multipliers, and a global bucket; the budget enforcer feeds actual token consumption back to quota state post-request; degradation is a controlled, intentional response
  • O-6 partial: the complexity classifier gates parallel execution at a configured threshold; a worker cap is enforced; per-request cost impact of parallel execution is not independently capped relies on the global rate-limiter quota
  • O-7 partial: No per-request timeout on embedding calls; recommended: per-request timeout in RAG pipeline embedding path

Risk Acceptance

Risk Acceptance

Not every finding warrants remediation, and a threat model that pretends otherwise is not useful to the people who have to fund it. Acceptance is a decision with three required parts: an explicit justification, a named owner, and a review trigger. The trigger is the important one - it is what stops an accepted risk from quietly becoming an unmanaged one when the system's assumptions change.

FindingClassBasis for acceptanceReview trigger
S-7 RAG over-retrieval Homogeneous user population holding equivalent clearance for all indexed content; document-level ACLs carry a per-document tagging cost disproportionate to risk under that assumption Any differentiation of user access levels - external, partner-facing, or cross-organizational
G-5 Internal resource URL exposure Knowledge base structure is not itself a protected asset; exposed URLs carry no authentication material and resolve only behind existing access controls Knowledge base contents reclassified as restricted
G-6 Excessive result-set return Pre-defined query functions constrain query shape to known patterns; result-size enforcement costs more than the residual risk under a fixed function set Query functions become user-extensible or dynamically generated

Review cadence: Quarterly, or immediately on any change to the user population, access model, or tool configuration. Each acceptance above rests on an assumption about who the users are and what the agent can invoke; when that assumption changes, the acceptance is void and the finding returns to the queue.
